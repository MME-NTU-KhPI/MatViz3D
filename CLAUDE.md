# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

MatViz3D is a Qt6/QML desktop application for microstructure modeling using cellular automata. It grows synthetic 3D grain structures on a voxel grid, assigns crystallographic texture (grain orientations) to them, and estimates the resulting effective stress/strain response and elastic stiffness either via a real ANSYS FEM run or an in-memory FFT (Moulinec-Suquet) homogenization solver.

## Build

Requires Qt 6 (developed against 6.8.3 / CI uses 6.6.3), a MinGW or GCC toolchain, and HDF5.

**Windows (qmake + mingw):**
```
C:\Windows\System32\cmd.exe /A /Q /K C:\Qt\6.8.3\mingw_64\bin\qtenv2.bat   # puts qmake/mingw32-make on PATH
qmake MatViz3D.pro
mingw32-make -j4
```
Or build in-place inside the existing Qt Creator shadow build dir: `build\Desktop_Qt_6_8_3_MinGW_64_bit-Debug\` (already has a generated `Makefile`; just `cd` there and run `mingw32-make`).

**Linux:**
```
qmake6 MatViz3D.pro
make -j$(nproc)
```

HDF5 paths are auto-detected in `MatViz3D.pro` (`C:\Program Files\HDF_Group\HDF5\<version>` on Windows, `/usr/include/hdf5/serial` on Linux). On macOS `MatViz3D.pro` finds libomp and HDF5 through `LIBOMP_DIR` / `HDF5_DIR` in the environment, else `brew --prefix`, else the two standard Homebrew prefixes (`/opt/homebrew` on Apple silicon, `/usr/local` on Intel), and stops with a message when one is missing.

Unit tests live in `tests/` (QtTest; `cd tests && qmake6 tests.pro && make -j && ./tests` — the project builds the production sources it needs without the QML entry point; on macOS it links Homebrew's libomp and HDF5 like the main `.pro`). Suites cover Polycrystall seeding/growth, wave nucleation, texture math, the Hill fit, the SVG exporter, the CLI/config parsers, the Lattice algorithm (every family group, union / carve-out / smoothing, honeycomb shape, material override, the cubic assembly's orbit distance and connectivity, the foams' Voronoi faces and edges and the random foam's round trip, the new minimal surfaces' expansions and every bio-inspired / architected form), the printability check, the FFT homogenizer (basic and CG schemes, Willot's rotated discretization, the sensitivity index and tensor), the cell decoder of the Neural tab (`TestCellDecoder`: the embedded weights load, the C++ forward pass matches PyTorch on a reference code, a code shifted by one position gives the cell shifted by 4 voxels, random codes are reproducible, a broken file is refused, `keepLargestBody` joins a body across the periodic faces and clears the rest), and its diffusion network (`TestCellDiffusion`: the header of `models/cell_diffusion.bin`, the request built as in training - moduli relative to the material, flags, clipping to the training range, what is not passed -, one pass of the network against PyTorch's numbers for dif2 step 30 000, dif4 step 20 000 or dif6 step 5 000 (whichever the file holds), a 3-step sampling at guidance 3 against PyTorch's code for dif4 step 20 000 or dif6 step 5 000, reproducible starting noise, a 3-step sampling with progress and stop, broken and cut files refused; the weights file is not in git, so without it - or with `MATVIZ_CELL_DIFFUSION` naming a missing file - the tests that need it are skipped), the request check of the Neural tab (`TestRequestCheck`: feasible requests pass, the Voigt bound at a density and along the printed layers, the Hashin-Shtrikman bound only for a cell asked to be isotropic, "same in all directions" against an anisotropy target (E z / E x 5 with one E for all directions; E max / min above 1 the same way, but allowed for equal axes typed per axis; a shear ratio only when G was given), the joint trace bound of E and G together (the request of 2026-11-15: E 610 and G 239 MPa at density 0.34 -> G at most 69 MPa with that E, both from density 0.47; the cell the network made fits at its density; a solid weaker across the layers is covered, a stiffer one is not), Poisson's ratios that make a compliance that is not positive, G and K of an isotropic cell, ratio targets against the axes, the Zener ratio and E max / min of a cubic cell, K from E and ν; no data), and its property predictor (`TestCellPredictor`: the header of `models/cell_predictor.bin`, the encoder's code and the 24 properties of a reference cell - a sheet gyroid - against PyTorch's numbers for pred1 step 14 000, a noised code at level 500 with another material, a cell shifted by 16 / 32 / 48 voxels gives the same answer, wrong sizes give nothing, broken and cut files refused; skipped without the file, like the diffusion tests). `TestSeedDistribution::testRandomSeedsUnchanged` fails in 6 rows on the macOS build (seen unchanged since 2026-11-04, before the Selector and Neural work; the cause has not been looked into). Beyond that, validate changes by building, running `qmllint <file>.qml` on touched QML, and exercising the relevant feature through the GUI or `--nogui --autostart` CLI path.

### solver_compare (standalone ANSYS-vs-FFT harness)

`solver_compare/solver_compare.pro` builds a separate console executable that reuses the real `StressAnalysis`/`StressAnalysisFFT` translation units (not a reimplementation) to A/B the two solvers on identical grain orientations for a given seed:
```
cd solver_compare
qmake solver_compare.pro
make -j
./solver_compare --help
```
ANSYS must be on PATH for `--solver both|ansys`; it degrades to FFT-only otherwise.

## Running

GUI: run the built executable directly.

Headless/scripted, via `commandline_parser.cpp` options (`--help` or `--help-json` for machine-readable JSON):
- `--nogui --autostart` — generate a structure with no UI and exit (add `--run_stress_calc` to also solve).
- `--nologo` (or `--no-logo`) — suppress printing the ASCII logo banner on startup.
- `--algorithm <name> --size <n> --points <n> --seed <n>` — structure generation (add `--animate` to step iteration by iteration instead of one shot). Available algorithms: `Voronoi`, `Composite`, `Probability`, `Polycrystall`, `DLCA`, `Lattice` (with `Moore`, `Neumann`, `Radial` supported as backward-compatible aliases).
- `--neighborhood <stencil>` — Polycrystall cellular automaton neighborhood stencil: `'Moore (26)'`, `'von Neumann (6)'`, `'Radial (18)'` (aliases: `Moore`, `Neumann`, `Radial`).
- `--minkowski_p <p> --periodic --voronoi_metric_preset <preset> --voronoi_mxx <m11> --voronoi_myy <m22> --voronoi_mzz <m33> --voronoi_mxy <m12> --voronoi_myz <m23> --voronoi_mxz <m13> --voronoi_metric <mxx,myy,mzz[,mxy,myz,mxz]>` — Voronoi tessellation and 3D Riemannian metric tensor controls (presets matching Probability algo: `Sphere (Circle)`, `Prolate (Needle)`, `Oblate (Disc)`, `Triaxial Ellipsoid`, `Superellipsoid (Cube)`, plus `Columnar (Z-axis)`, `Columnar (X-axis)`, `Rolled (Orthotropic)`, `Sheared (45° XY)`, `Custom`).
- `--halfaxis_a <a> --halfaxis_b <b> --halfaxis_c <c> --ellipse_order <p> --orientation_angle_a <deg> --orientation_angle_b <deg> --orientation_angle_c <deg> --stefan_number <n> --prob_matrix_mode <volume|surface> --prob_preset <preset>` — Probability superellipsoid kernel, matrix mode, and orientation controls (`--periodic` applies here too).
- `--wave_generation --initial_nuclei <n> --wave_peak_fraction <0..1> --wave_end_fraction <0..1>` — Probability continuous wave nucleation (transformation-fraction controlled kinetics).
- `--composite_dim <1d|2d|3d> --composite_packing <square|hexagonal> --fiber_volume_fraction <0..1> --fibers_per_row <n>` — Composite RVE layout (`--periodic` applies here too).
- `--fiber_aspect_ratio <a/b> --fiber_angle_scatter <deg> --fiber_center_jitter <0..1> --fiber_allow_overlap` — Composite RVE imperfections.
- `--matrix_material <name> --fiber_material <name>` — the two Composite constituents (both from `material_properties.db`); replaces `--material` for that algorithm.
- `--lattice_family <gyroid_sheet|gyroid_skeletal|schwarz_p_sheet|schwarz_p_skeletal|schwarz_d_sheet|schwarz_d_skeletal|iwp_sheet|iwp_skeletal|simple_cubic|bcc|fcc|octet|honeycomb|reentrant|spinodoid|fourier_sheet|fourier_skeletal|noise_sheet|noise_skeletal|plate_sc|plate_bcc|plate_fcc|plate_sc_bcc|plate_sc_fcc|plate_bcc_fcc|plate_sc_bcc_fcc|spheres_sc|spheres_bcc|spheres_fcc|cylinders_axes|cubic_assembly|foam_kelvin|foam_rhombic|foam_weaire_phelan|foam_random|mycelium|neovius_sheet|fischer_koch_sheet|lidinoid_sheet|glass_sponge|chiral_twist|woven|bouligand|diamond_ball_stick|reentrant_3d|radiolarian|trabecular_bone|wood|cuttlebone|turing|hierarchical_gyroid> --cells_per_edge <n> --relative_density <0..1> --lattice_grading <0..0.9> --lattice_jitter <0..1>` — Lattice cell family, cells per cube edge, target solid fraction and imperfections; `--orientation_angle_a/b/c` rotate the lattice, `--material` is the solid (default `PETG`).
- `--spinodoid_theta_x/y/z <0|5..90>` — spinodoid cone half-angles about the axes (all 90 = isotropic, one open cone = lamellar, two = columnar); `--fourier_terms <n> --fourier_kmin <k> --fourier_kmax <k> --fourier_decay <p>` — random Fourier-series draw; `--fourier_file <path>` — one wave per line (`kx ky kz amplitude phase`), overrides the draw; `--noise_smooth <frac>` — smoothed-noise families: Gaussian sigma of the blur as a fraction of the cube edge.
- `--assembly_struts/plates/shells/holes <n> --assembly_spread <s> --assembly_file <path>` — `cubic_assembly`: members drawn in the asymmetric unit (0..12 / 0..12 / 0..4 / 0..8, default 3 / 2 / 0 / 1), thickness weights in [1 - s, 1 + s], or the members read from a file (`kind x0 y0 z0 x1 y1 z1 x2 y2 z2 radius weight`, the last column of a window is the index of the member it cuts).
- `--foam_mode <walls|windows|edges> --foam_frame <f> --foam_bubbles <n> --foam_file <path>` — foam families (3D honeycombs): closed cells, a window in every face (the wall reaches `c + f` bubble sizes from the face's edges) or the edges only; `foam_random` sites per cell (default 8) or read from a file (`x y z` per line, cell units).
- `--mycelium_mode <substrate|polypore|mat|layered> --mycelium_length <cell edges> --mycelium_spores <n> --mycelium_unit <cell edges> --mycelium_angle <deg> --mycelium_wiggle <0..1> --mycelium_fuse <cell edges> --mycelium_taper <0.3..1> --mycelium_binding <share> --mycelium_align <0..1> --mycelium_anchors <share> --mycelium_poor <level> --mycelium_file <path>` — `mycelium`: growth mode and settings (defaults 22 / 0 = mode default / 0.25 / 60 / 0.25 / 0.05 / 0.75 / 0.36 / 0 / 0.25 / 0.25), or the hyphae read from a file (`ax ay az bx by bz [weight]` per line, cell units).
- `--lattice_cell_mm <mm>` — physical size of one Lattice cell (voxel = cells × cell_mm / size); `--print_min_wall_mm <mm> --print_max_overhang_deg <deg> --print_max_thin_fraction --print_max_island_vox --print_max_components --print_max_unsupported_fraction --print_min_directions` — printability thresholds (defaults 0.8 mm, 45°, 0.02, 8 voxels, 1 body, 0.05, 3 directions); `--require_printable` — headless: skip the stress solve and exit with code 3 when the Lattice structure fails the check (the geometry and its report are still written to `--output`). `--remove_islands` — Lattice: every floating island (a solid component that is not the body, any size) becomes void in `Lattice::finish()` before the density, the wall estimate, the printability check and the solve (`removeIslands()` in printability.cpp, the body defined as in the check); the HDF5 geometry group then records `remove_islands`, `islands_removed`, `island_voxels_removed`. Dataset v1 passes it from 2026-11-16 (`remove_islands: true` in the config); without it specks of up to `print_max_island_vox` (8) voxels stay in the cell.
- `--lattice_metric_y <f> --lattice_metric_z <f>` — Lattice thickness metric (0.25..4, default 1, x is 1; 2026-11-16): the distance families measure distances with diag(1, my², mz²), so members whose thickness runs along an axis with a factor above 1 come out thinner and, once the level is solved for the density, the others thicker — a continuous anisotropy knob for the regular families (a cubic cell becomes tetragonal about Z for my = 1, orthorhombic for three different values; still periodic, mirror planes kept). Strut lattices (simple cubic, BCC, FCC, octet) and plate lattices exactly (plate n.x = d: |n.x − d| / |n| in the inverse metric), uniform-wall sheets to first order (|f| / |∇f| with the gradient's length in the inverse metric), the cubic assembly through its fold (`assemblyFieldMetric()`: the metric follows the axes into the asymmetric unit, every member is measured with its images under the six swaps of the unit's axes so the field stays continuous across the diagonal mirror planes, and a point inside a member's own window skips the member and all its images, as the plain field does — without that rule the images filled the windows: 19 608 voxels changed and 70 % closed pores at metric 1). The {111} plates (plate_fcc) all lean to Z alike, so a metric along Z thickens or thins them all the same and plate_fcc alone stays cubic; the body-diagonal struts (BCC) likewise change little. Other families ignore it with a log line. Metric 1 keeps every cell bit for bit (plate_sc, octet, cubic_assembly, schwarz_p_sheet against the previous binary; the assembly path forced at metric 1 matched the plain one on three seeds); the wall estimate is divided by the largest factor. HDF5 geometry gets `lattice_metric_y` / `lattice_metric_z` only when one is not 1; `tools/dataset` passes `p_lattice_metric_y` / `p_lattice_metric_z`. `testThicknessMetric` (TestLattice) checks the symmetry, the closed form of the plates and the density.
- `--material <name>` — material from `material_properties.db` (Cu, Fe, W, ...); supplies the cubic constants both stress solvers use and the lattice the texture presets are built for.
- `--material_iso <E_GPa,nu>` / `--material_ti <E_GPa,nu,r>` — the solid material as numbers instead of a database row (isotropic, or transversely isotropic about the build axis Z with E_z = r·E and G_xz = G_yz = r·G); used by Lattice's phase assignment and recorded as `mat_e_gpa`, `mat_nu`, `mat_aniso`, `mat_source` in the HDF5 geometry group (config keys `mat_e_gpa`, `mat_nu`, `mat_aniso`). `--no_fields` — do not store per-voxel stress/strain fields (`ls_k/results`) in HDF5; matrices, voxels and metadata stay, which turns a ~40 MB 64³ stiffness file into ~1 MB for dataset runs.
- `--texture <random|extrusion|rolling|recrystallization|shear|scattered_cube> --lattice <fcc|bcc> --scatter <deg>` — crystallographic texture preset (`--lattice` overrides the material's lattice).
- `--run_stress_calc --solver <ansys|fft> --stress_mode <stiffness|single|dataset> --eps <exx,eyy,ezz,exy,eyz,exz>` — stress analysis.
- `--fft_scheme <auto|basic|cg> --fft_tol <tol> --fft_max_iter <n>` — FFT solver scheme (auto = CG for porous or high-contrast cells, basic otherwise), convergence tolerance and iteration cap.
- `--fft_discretization <continuous|rotated> --fft_void_eta <eta>` — Green-operator discretization (`continuous` = Moulinec-Suquet, the default; `rotated` = Willot 2015, converges for true pores; aliases `ms` / `willot`) and the stiffness of the void phase as a fraction of the solid C11 (default 1e-4; soft bending-dominated cells need 1e-6).
- `--output <file>`, `--working_directory <dir>`, `--num_rnd_loads <n>`, `--np <n>`. With `--nogui --autostart` and no `--run_stress_calc`, `--output` writes the voxel grid and geometry metadata alone (`ExportController::writeGeometryHDF5`), so a generation-only run still leaves an HDF5 file.
- `--screenshot <file.png|file.pdf>` (with `--nogui --autostart`) — a picture of the generated structure without any window (`ExportController::headlessScreenshot()`: an `OpenGLWidgetQML` item with no window builds the mesh and camera, `renderHeadless()` renders it in an offscreen GL context, then the Save pipeline: crop, triad, DPI, PDF). `--dpi <n>` (300), `--background theme|white|transparent` (white), `--width_cm <cm>` (0 = the view size), `--view_size WxH` (1200x900 logical px), `--outlines off|boundaries|voxels`, `--pdf_vector`. Runs before the stress solve and shows the structure only (no field: the nogui solve does not feed a 3D view); exit code 4 when no GL context can be made (a Linux server needs a GL-capable `QT_QPA_PLATFORM`). `tools/screenshot/check_screenshots.py --exe <MatViz3D>` runs five fixed cases and checks the PNGs against `tools/screenshot/reference/` (mean difference ≤ 0.6 per channel, ≤ 0.4 % of pixels off by more than 48; the boundary outlines alone change 1.5 %), their DPI tag and width in cm, and the PDFs from their bytes (one page of the right width, no JPEG, no image in the vector model, no embedded font); `--update` rewrites the references (made on Windows / Qt 6.12; regenerate and inspect on another platform).
- `--browse <path>` — GUI: switch the Data panel to its Dataset tab on a dataset folder (`manifest.csv` + `cells/`), its manifest or one cell file. `MATVIZ_SNAPSHOT=<prefix>` (optionally `MATVIZ_SNAPSHOT_HEIGHT=<px>`) saves every visible window as `<prefix>_<title>.png` after ~4.5 s and quits — the way to check a QML window without a screen recorder.
- `MATVIZ_EXPORT=<prefix>` (GUI; optionally `MATVIZ_EXPORT_DPI=<dpi>`, `MATVIZ_EXPORT_DELAY=<ms>`, default 5000) — after the delay write what **Save** and **Copy** produce for the 3D view with the current settings (`<prefix>_save.png`, `<prefix>_copy.png`; Copy also goes to the clipboard and the log lists its formats), the transparent export with the light and the dark overlay (`<prefix>_transparent.png`, `<prefix>_transparent_dark.png`) and the bare capture (`<prefix>_raw_transparent.png`), then quit: the scripted check of the screenshot pipeline (`ExportController::debugExport`). `MATVIZ_EXPORT_GRAB=1` forces the old `grabToImage()` path for before / after comparisons. The 3D view is captured by a real off-screen render on the render thread (`OpenGLWidgetQML::requestCapture()` -> `RenderOpenGL::renderOffscreen()`: multisampled FBO of the export size, up to 8x MSAA within ~1.5 GB, the same camera, no corner triad, theme / white / transparent clear, read back unflipped because the screen shows the FBO with GL's bottom row on top); other items and an unexposed window (no frame within 10 s) fall back to `grabToImage()`. `ExportController::processScreenshot()` takes `ScreenshotOptions` and works in ARGB32_Premultiplied throughout (crop by alpha on a transparent background, by colour otherwise); an opaque result is written as RGB32. The screenshot popup sets `background` (Auto = Save on the theme, Copy on white / Theme / White / None) and `overlayStyle` (Auto = dark on the theme, light otherwise / Light / Dark); the gizmo has a halo in the overlay's colour and the legend card a translucent backing on a transparent export. The clipboard gets PNG bytes (`image/png`, and on Windows the registered `PNG` format Office and browsers read) plus the plain image (`ExportController::putImageOnClipboard()`).
- Export sizes and fonts (2026-11-22): every exported label (legend, axis triad) is drawn in Inter, registered from `:/fonts/` by `ExportController::registerFonts()` in main.cpp (`exportFontFamily()`, "Segoe UI" / the system sans before it), at sizes in points: pixel size = pt × DPI / 72 (`overlayFont()`; title 10.5 pt, values 9 pt, × `ScreenshotOptions::overlayScale`). The screenshot popup sets **Resolution** (`ExportController::resolution`: Screen / 150 / 300 / 600 DPI; Screen means the window's own DPI, `effectiveDpi()` — before, the overlays were drawn at 300 DPI on a 96 DPI frame) and **Width** (`widthCm`, 0 = the view's size; `MATVIZ_EXPORT_WIDTH_CM`): with a width the capture is rendered at 1.5× the target, cropped, resampled to exactly `widthCm` at the DPI, and the overlays shrink to `overlayScale` 0.8 with the legend at most 60 % of the figure. Legend ticks: a common power of ten goes into the title ("(×10⁸)"), mantissas with 3 significant digits, and the 25 / 75 % (then the 50 %) labels are dropped when neighbours would touch. **Save as SVG (image)** (`saveAsSVG` / `saveAsSVGTo`, `writeEmbeddedSvg()`) is the same pipeline in an SVG sized in mm; MATVIZ_EXPORT also writes `<prefix>_image.svg`. The statistics, texture and HDF5 chart windows save PNGs through `exportController.saveItemImage(item, path)` (grab at the export DPI, DPR-corrected, DPI in the file) instead of a fixed 2× grab. When the window renders no frame (not exposed, or none within 10 s — a display that went off), the capture is rendered headless: `OpenGLWidgetQML::renderHeadless()` builds a second `RenderOpenGL` in an offscreen-surface context on the GUI thread, set up by `configureRenderer()` like the window's (tensor glyph / streamline meshes are not copied).
- PDF export (2026-11-22): **Save** offers PNG or PDF (a `.pdf` name in `saveImageTo()` too); `savePdfTo()` writes one page of the figure's physical size (pixels at the DPI, `QPdfWriter` at that resolution, zero margins). The screenshot is first laid out by `ExportController::layoutScreenshot()` (a `Composition`: cropped / resampled model image, crop rect and resample factor in scene pixels, legend data and card rect, triad centre, overlay scale), which `processScreenshot()` paints into an image and `writePdf()` onto the page; `paintOverlays()` draws the legend card and the axis triad as vectors on either painter (legend text stays text, Inter embedded; the triad letters are outlines). The model is the image (stored losslessly: `QPainter::LosslessImageRendering`, without it Qt picks JPEG) or, with **PDF model: Vector** (`ExportController::pdfVectorModel` / `pdfModel`), one polygon per visible voxel face from `OpenGLWidgetQML::vectorFaces()`: projected with the renderer's camera at the capture size, back faces dropped by winding, sorted far to near, shaded on the CPU like the fragment shader (depth model with per-face AO, or classic), outlines as lines per edge mask, each polygon also stroked thinly in its own colour against anti-aliasing seams. The vector model carries the scene axes as items of the same list (`ShadedFace::kind` 1 shaft pieces, 2 arrowheads; 48 pieces per shaft, each sorted by its own depth, pushed 0.6 voxel back so the faces sharing a cube edge hide it as the GL depth test does). On a PDF page the legend's text goes in as glyph outlines (`drawLabel()`): Qt embeds a variable font (Inter) once per document, so as text every label took the weight of the first one drawn. MATVIZ_EXPORT writes `<prefix>_pdf.pdf` and `<prefix>_pdf_vector.pdf`; `pdfinfo` / `pdfimages -list` / `pdftoppm` (TeX Live) check them.
- `MATVIZ_SHADING=0|1`, `MATVIZ_AO=<0..1>`, `MATVIZ_DEPTHCUE=<0..1>` (GUI) — shading of the 3D view at start, for scripted before / after shots. The view has two shading models (`OpenGLWidgetQML::shadingModel`, the **Shading and depth** toolbar popup): 0 classic (six lights fixed to the model, the look before 2026-11-22; also what the material database's stiffness-surface renderer gets, since it never sets the uniform) and 1 depth, the default: camera-fixed key light from the upper left and a fill from the right, hemispherical ambient (camera -Y is up on screen, the FBO is shown flipped), per-vertex voxel ambient occlusion (`aoStrength`, default 0.85; the mesh builder counts the 3 voxels around each face corner in the layer outside the face, level 0..3 in `GlVertex::ao`, the former padding byte, and splits each quad along its brighter diagonal), depth cueing toward grey and dark on the far side of the scene's bounding sphere (`depthCue`, default 0.35) and a floor of 0.28 of the base colour. In the default dimetric view a cube's top / left / right faces get 0.97 / 0.76 / 0.60 of the base colour (classic: the top was the darkest).
- `MATVIZ_OUTLINES=0|1|2`, `MATVIZ_OUTLINE_WIDTH=<px>`, `MATVIZ_ORIENTATIONS=1` (GUI) — outlines and crystal axes at start, for scripted shots. Outlines (the toolbar's former wireframe toggle; kind and width in the **Shading and depth** popup; `OpenGLWidgetQML::outlines` / `outlineKind` / `outlineWidth`) are drawn by the lit fragment shader on the faces, not by GL lines (whose width the core profile caps at 1 and which ignored the export DPI): the voxel builder packs into `GlVertex::ao` (`glVoxelPack()`) the AO level (bits 0-1), a mask of the face edges that are boundaries (bits 2-5) and the vertex's corner (bits 6-7, which the vertex shader turns into face coordinates); the fragment measures the distance to the edges in pixels with `fwidth` and darkens the shaded colour (×0.30 boundaries, ×0.55 voxels). Kind 1 = every voxel edge (at most a fifth of a voxel wide, fading out below 3 px per voxel), 2 = boundaries: another grain across the edge, a convex corner (nothing across and nothing below) or a concave one (a wall at least 2 voxels high) — one-voxel staircase steps of curved surfaces are not boundaries. Width is in logical pixels × DPR on screen, × export size / view size in a capture (`RenderOpenGL::lineScale()`). The crystal-axis glyphs and the scene / corner axes are screen-space quads (`RenderOpenGL::drawThickLines()`, `kLineVertexShader`) with the same scaling. Overlay meshes are drawn with outlines off; any other `GlVertex` mesh keeps `ao = 3`.
- `MATVIZ_PALETTE=<0..6>` (GUI) — field colormap at start (`matviz_cmap::Palette`: 0 Rainbow (default), 1 Cool-Warm, 2 Red-Blue, 3 Viridis, 4 Grayscale, 5 Turbo, 6 Cividis; ordinals are QML API, append only). Turbo / Viridis / Cividis / Cool-Warm are 17-stop samples of matplotlib's tables; Cool-Warm is Moreland's (light grey middle: pure white vanished on a white page) and Red-Blue its mirror. Grain colours come from `matviz_cmap::grainColor(i)` (colormap.hpp, also used by VRML export): opaque OKLCH, golden-ratio hue steps, chroma 0.19 within the sRGB gamut, lightness 0.71 + 0.11 cos(h - 110°) ± 0.045 by id parity — OKLab dE between ids i and i+1 ≥ 0.24 for any count (evenly spaced HSV gave 0.008 at 30 grains, 0 at 200), ≥ 0.21 to a white page on every lit face.
- `--neural <seed>` — GUI: switch the Data panel to its Neural tab and generate the cell of that seed (0 = a new seed) with the form as it stands: through the diffusion network when `models/cell_diffusion.bin` is found, else from a random code (with `MATVIZ_SNAPSHOT` this is the scripted check of the tab; a generated cell takes ~45 s with the dif4 / dif6 weights (two passes of the network per step) and ~10 s with dif2, so add `MATVIZ_SNAPSHOT_DELAY=80000` - the delay in ms, default 4500). `MATVIZ_CELL_DIFFUSION=<file>` names the diffusion weights (only that file is tried; a missing one is the way to see the tab without the model), `MATVIZ_CELL_PREDICTOR=<file>` the weights of the property predictor in the same way (a missing one: the tab without the `predicted` column), `MATVIZ_CELL_DECODER=<file>` reads the decoder weights of another training run instead of the built-in ones.
- `--neural_compare` — GUI, with `--neural`: as soon as the cell is generated, solve it the way the dataset was solved and fill the tab's "asked and obtained" table (the **Solve and compare** button; seconds on the GPU when an interpreter with PyTorch is found, else minutes on the CPU, where `--np` sets the threads; `MATVIZ_GPU_SOLVER=0` forces the CPU, `MATVIZ_GPU_PYTHON=<interpreter>` / `MATVIZ_GPU_SCRIPT=<file>` name the GPU solver's interpreter and script). The log gets one `[Neural]` line per target. With `MATVIZ_SNAPSHOT` and no `MATVIZ_SNAPSHOT_DELAY` the shot is taken 1.5 s after the solve has ended instead of at a fixed time.
- `--help-json` — dump complete CLI options, algorithms, materials, texture presets, and executable recipes as JSON for automation/agents.

## Architecture

### Global state: `Parameters` (parameters.h/.cpp)
A singleton (`Parameters::instance()`) exposing almost all cross-cutting state as **static** members (grid `size`/`points`, RNG `seed`, the live voxel grid `Parameters::voxels` (`int32_t***`), `Parameters::textureComponents`, stress-solver settings, etc.). It's also registered into QML as a singleton type (`import parameters 1.0`). Because the members are static, there is effectively one global mutable state shared by the algorithm layer, the texture editor, and both stress solvers — read/write it directly rather than threading state through constructors.

### Structure generation
`Parent_Algorithm` (parent_algorithm.h) is the base class for every algorithm; each owns the voxel grid (`int32_t*** voxels`, x/y/z grain-id volume) and iterates `Next_Iteration()` until `getDone()`. `MainWindowAlgorithmHandler` drives execution (`runAlgorithm`/`runStressCalculation`) and pushes results into the 3D view.

**Adding an algorithm (the plugin model).** `voronoi.cpp` and `composite.cpp` are the reference. An algorithm is described by one `AlgorithmPlugin` (algorithmplugin.h) carrying its name, parameter schema and factory together, declared at namespace scope in its own .cpp with `MATVIZ_REGISTER_ALGORITHM(...)`. That static registrar puts it in `AlgorithmFactory` before `main()` runs, so nothing else has to name it: `SchemaController::algorithmNames()` feeds the UI combo box straight from the registry, and `schemaFor()` builds the parameter panel. Adding an algorithm = adding one .h/.cpp pair plus the two `.pro` lines. Shared schema pieces live in algorithmplugin.cpp — `baseAlgorithmSchema()` (size/points/wave), `materialParamField()`, `textureParamFields()`.

All algorithms in MatViz3D — `Voronoi`, `Composite`, `Polycrystall`, `DLCA`, `Probability` and `Lattice` — are self-registering `AlgorithmPlugin`s declared in their own `.cpp` with `MATVIZ_REGISTER_ALGORITHM(...)`. Historical algorithms `Probability_Circle` and `Probability_Ellipse` are unified into `Probability` as shape presets ("Sphere (Circle)", "Triaxial Ellipsoid", etc.), and historical CA algorithms `Moore`, `Neumann`, and `Radial` are unified into `Polycrystall` with selectable neighborhood stencil ("Moore (26)", "von Neumann (6)", "Radial (18)").

`ParamField` (paramfield.h) types are `Int/Double/Bool/Enum/PointsMode/Action`, rendered by `DynamicParamBlock.qml` (the QML switch matches the enum ordinal). Two indirections keep schemas buildable during static initialisation, before `QCoreApplication` exists: `optionsProvider` names a runtime source for `Enum` options (`"materials"` -> the SQL table), and `action` / `actionOnValue` raise `SchemaController::actionTriggered(id)` for QML to turn into a window (this is how the texture dropdown's "Custom (editor)" entry and the "Open editor..." button reach `TextureView.qml`).

**`Polycrystall` (polycrystall.h/.cpp)** — cellular automaton grain growth with selectable neighborhood stencils: 26-neighbor Moore, 6-neighbor von Neumann, and 18-neighbor Radial. Features OpenMP-parallelized growth front propagation with atomic CAS synchronization (`__sync_bool_compare_and_swap`), periodic boundary conditions (`--periodic`), material and crystallographic texture support. Legacy names `Moore`, `Neumann`, `von Neumann`, and `Radial` remain supported as CLI/factory aliases.

**`Voronoi` (voronoi.h/.cpp)** — the reference algorithm. Assigns each voxel to the nearest seed under a generalized Minkowski L_p metric and 3D Riemannian metric tensor $\mathbf{M}$ (`Parameters::minkowski_p`, `Parameters::voronoi_mxx .. voronoi_mxz`, with GUI presets matching Probability algo: `Sphere (Circle)`, `Prolate (Needle)`, `Oblate (Disc)`, `Triaxial Ellipsoid`, `Superellipsoid (Cube)`, plus `Columnar (Z-axis)`, `Columnar (X-axis)`, `Rolled (Orthotropic)`, `Sheared (45° XY)`, and `Custom`), with minimum-image offsets when `Parameters::is_periodic`. A diagonal metric tensor scales grain dimensions along Cartesian axes to model rolled or columnar microstructures, while off-diagonal components rotate the principal elongation axes. The nearest-seed search uses a CSR bucket grid over the seeds with an expanding-ring bound ($s_p \ge c_{\text{bound}} \cdot \text{gap}^p$, scaled by the metric tensor's minimum eigenvalue) over tabulated $|d|^p$ arrays, maintaining maximum speed. The tessellation is exact and one-shot, but `Next_Iteration()` still reveals it in distance bands so animation/GIF recording work and end on the identical structure. Set `MATVIZ_VORONOI_VERIFY=1` to cross-check the bucket search against brute force and the banded reveal against the exact tessellation.

**`Composite` (composite.h/.cpp)** — fiber-reinforced RVE, and the second plugin-style algorithm. One, two or three orthogonal families of continuous elliptical fibers (`composite_dim` = 1D along Z / 2D along X,Y / 3D along X,Y,Z) on a square or row-staggered hexagonal lattice. Each family is decided entirely in the 2D plane normal to its axis and rasterized into an id plane (ids plus the normalised elliptical radius), which a single O(N^3) combine pass then merges — so cost is O(F·N^2 + N^3), not voxels × fibers. Crossings go to whichever fiber the voxel sits **deepest inside**, and exact ties are dealt out alternately by `(x+y+z) % candidates`. Both halves of that rule matter: taking the first family listed instead gave family X ~1.8x the volume of family Y in a 0/90 layup, and on a symmetric lattice a quarter of the crossing volume ties exactly. With the rule in place a 2D crossed cell comes out with Ex == Ey to the digit, and a 3D orthogonal one with Ex == Ey == Ez to 0.2%.

`fiber_volume_fraction` is an *input*, not an outcome: the fiber semi-axes are bisected against the volume fraction measured on a sub-sampled copy of the grid (`m_coarseN`, capped at 128) until the target is hit, which matters for 2D/3D where the families intersect and the areas do not simply add. Unless `fiber_allow_overlap` is set, the target is clamped to the no-overlap packing limit and the clamp is logged. Because Vf(r) is a staircase on a voxel grid — and on a perfect lattice every fiber crosses each step together — the bisection returns the radius whose *measured* fraction is closest to the target rather than whichever side it converged on; the achieved value is always reported.

The imperfection knobs (`fiber_center_jitter`, `fiber_aspect_ratio`, `fiber_angle_scatter`) all run off `Parameters::seed`. Ellipse area is held at `pi*a*b = pi*r^2`, so a/b changes shape at constant Vf. When the ellipses are aligned (zero scatter) the lattice is stretched by the same a/b, which keeps the packing ceiling at the circular value for any aspect ratio; once the fibers can rotate that stretch buys nothing and the lattice stays isotropic, so the reachable Vf falls off as ~1/(a/b). Jittered centers are rejection-sampled against their neighbours unless overlap is allowed. `Next_Iteration()` re-rasterizes at a growing radius, so the animated path ends on exactly the structure `Generate_To_End()` produces in one shot.

The matrix is grain id 1; every fiber gets its own id from 2 up, because orientation is carried per grain id and each fiber's material frame comes from its own axis and ellipse angle. Composite publishes a `PhaseAssignment` (matrix material + fiber material + per-fiber orientation) that both solvers read — see "Multi-phase materials" below.

**`Probability` (probability_algorithm.h/.cpp)** — stochastic cellular automaton with anisotropic superellipsoidal shape kernels (`|x/a|^p + |y/b|^p + |z/c|^p <= 1`) and 3D Euler rotation angles. Supports shape presets (`Sphere (Circle)`, `Prolate (Needle)`, `Oblate (Disc)`, `Triaxial Ellipsoid`, `Superellipsoid (Cube)`, and `Custom`), periodic boundary conditions, thermodynamic Stefan cooling limits, and standard material/texture assignments. The kernel transition matrix supports two calculation modes via `Parameters::prob_matrix_mode`: `"Volume Sampling"` (Monte Carlo volume sampling) and `"Surface Flux"` (radial reach and Voronoi cone partitioning to project directional boundary flux onto the 26-neighbor stencil). Continuous wave nucleation (`is_wave_generation`) introduces nuclei dynamically following a Gaussian error function ($\text{erf}$) trajectory governed by transformation fraction $X$, peaking at `wave_peak_fraction` and completing by `wave_end_fraction`. Growth is OpenMP-parallelized using pure integer hash-based dice rolls (`hashDice`) and an atomic minimum claim grid (`m_claimGrid`), guaranteeing 100% bit-for-bit reproducible structure realization across runs for a given seed regardless of thread count or thread arrival order. Historical names `Probability Circle` and `Probability Ellipse` remain supported as CLI/factory aliases.

**`Lattice` (lattice.h/.cpp, latticefamily.h)** — periodic cellular metamaterial RVE: one solid phase (grain id 1) and void (id 0), tiled from `cells_per_edge` unit cells of one family. The solid is the sublevel set `{F(x) <= c}` of a family-specific field: the trigonometric level set `f` of a TPMS (gyroid, Schwarz P, Schwarz D, IWP) with `F = |f|` for *sheet* and `F = f` for *skeletal* solids; the distance to the nearest strut centre-line for the strut families (simple cubic, BCC, FCC, octet; segments in one cell, 27 periodic images); the in-plane distance to wall centre-lines for the honeycombs (regular hexagonal, `theta = +30°`, and re-entrant/auxetic, `theta = -30°`, built from two staggered vertical ribs and four inclined walls; a hexagonal tiling is not periodic on a square, so the cell count along Y is rounded and the stretch factor reported); and a Gaussian random field from ~40 waves on the integer lattice for the spinodoid, so it is periodic in the cube by construction and reproducible from `Parameters::seed`; its wave directions can be confined to the union of cones about the axes (`spinodoid_theta_x/y/z`, Kumar et al. 2020: 90/90/90 isotropic, one open cone lamellar, two columnar), so the statistics rather than a name define the geometry. The open `fourier_sheet` / `fourier_skeletal` families take F as a sum of `fourier_terms` cosine waves on the integer lattice with amplitudes ~ |k|^-`fourier_decay` in the band [`fourier_kmin`, `fourier_kmax`] waves per edge (distinct vectors, normalized to unit variance, seeded) — or read verbatim from `fourier_file` (one `kx ky kz amplitude phase` per line; a zero vector is ignored, an unreadable file falls back to the draw with a warning). The waves actually used are published to `Parameters::lattice_wave_terms` and written to `geometry/lattice_wave_terms` in the HDF5 file: that row list is the geometry vector a property-to-geometry network outputs. The four TPMS families publish their exact finite Fourier expansions in the same slot (`Lattice::tpmsWaves()`: gyroid 6 waves, Schwarz P 3, Schwarz D 4, IWP 9, with k scaled by `cells_per_edge`), so every level-set cell in a dataset shares one representation. The `noise_sheet` / `noise_skeletal` families are the most random printable option: Gaussian white noise on a fixed 64^3 grid whatever the cube size (`kNoiseGrid`, latticefamily.h; seeded), blurred by a periodic separable Gaussian of sigma `noise_smooth` cube edges (three 1-D passes, kernel radius 3 sigma), normalized to unit variance, and read between its nodes (node i at (i + 1/2) / 64) by periodic Catmull-Rom interpolation (`Lattice::noiseAt()`). So one seed is one foam on every grid: a 64^3 cube reads the nodes exactly (cells made at 64^3 before the change are bit-identical), a 128^3 one overlaps it by 95-98 % (drawn on the cube's own grid it was another foam, overlap 0.21); `geometry/noise_grid` records the grid. `cells_per_edge` plays no role and the geometry vector is just (seed, smoothing, density). Barely smoothed noise is dust (many components); smoothing of about a wall thickness makes it a random foam. `--fourier_symmetry cubic` replaces every drawn (or file) wave by its orbit under the 48 symmetries of the cube with the same amplitude and phase (`Lattice::symmetrizeWaves()`): the orbit sum is invariant under the whole group for any phase, so the random cell has full cubic symmetry and a cubic stiffness (Ex = Ey = Ez); `fourier_terms` then counts generators and the published wave list holds the expansion. The **plate lattices** `plate_sc` ({100}), `plate_bcc` ({110}), `plate_fcc` ({111}) and their unions `plate_sc_bcc`, `plate_sc_fcc` (the Berger/Tancogne-Dejean cubic+octet plates that reach the Hashin–Shtrikman bound), `plate_bcc_fcc`, `plate_sc_bcc_fcc` take F as the distance to the nearest plate mid-plane in cell units (so c is half the plate thickness; `Lattice::plateField()`); `--plate_hole d` punches a circular hole of diameter d cell edges along the normal through every panel centre (face centres for {100}, the cell centre for {110}, the triangle centroids ±(1/3,1/3,1/3)·signs for {111}): inside a hole the plate's own field is +inf, so the hole is void for that plate only and the density is still solved exactly. `--lattice_union <family>` unites a second family with the first, F = min of the two fields with one shared level c (plates + octet struts, TPMS sheet + struts, ...); the second family may not be a random one (shared state) and two strut/honeycomb families may not be paired (one segment table), both refused with a warning. `--lattice_subtract <family> --lattice_subtract_size s` carves the sublevel set `{F3 <= s}` of a third family out of the solid (`rawField()` returns +inf there, so the level is solved on what remains): `plate_sc_fcc` minus `spheres_bcc` at 0.3 gives spherical windows, minus `cylinders_axes` gives round channels through the face centres. The site primitives `spheres_sc / spheres_bcc / spheres_fcc` (F = distance to the nearest lattice site, c the radius) and `cylinders_axes` (distance to the three axis lines through the face centres) exist mainly for that; alone, spheres below the touching radius are separate bodies and fail the printability check. The **cubic assembly** (`cubic_assembly`) is the free-form family: cells with full cubic symmetry of the kind topology optimization and generative models produce. Members are drawn from the seed in the asymmetric unit of Pm-3m, the orthoscheme `0 <= z <= y <= x <= 1/2` (vertices: cube corner, edge midpoint, face centre, cell centre), and every point is folded into it (`foldToUnit()`: per axis `min(x, 1 - x)` of the wrapped coordinate, then sorted). Pm-3m is generated by the reflections in the walls of that unit, so for a set inside it the folded distance equals the distance to its whole orbit (`testCubicAssemblyIsTheOrbitDistance` checks this against a brute force over 48 x 27 images); spherical shells reach outside the unit and carry their image centres (`finishMember()`). Members: `assembly_struts` segments, `assembly_plates` triangles (`triangleDistance()`), `assembly_shells` spheres about the special positions only (a centre in general position has 48 images per cell and fills the cell with surfaces; radius <= 0.47 about corners / cell centres, <= 0.34 about face centres / edge midpoints, so neighbours do not fuse into closed foam), `assembly_holes` windows. F = distance to the nearest member / its thickness weight (`assembly_spread`). Connectivity is by construction: the first member spans an edge or a wall of the unit (an SC / FCC / BCC strut network or {100} / {110} / mid-plane plates) and every later one starts on a point of an earlier one. A window is a ball that removes the material of its host plate / shell (and of plates coplanar with it) only, like `plate_hole`; windows keep clear of every point a member stands on, of a plate's free edges (an edge on a wall continues in the mirror image unless the whole triangle lies in that wall) and of their own mirror images (distance to each wall not through the centre > r, or a merged ring of images cuts out an island). A backbone plate always gets a window at one of its special positions and each shell one on a symmetry axis, so the cells stay open; random plates may not lie in a wall. Without windows a drawn cell is always one body; the remaining failures are thin walls and smoothing dust (trial of 60 dataset draws: ~50 % printable, ~1 island). The members go to `Parameters::lattice_assembly_terms` and `geometry/lattice_assembly_terms` (kind, three points, radius, weight; float-exact, so `assembly_file` with the table rebuilds the cell bit for bit). `--lattice_smooth sigma` (cell edges) samples the complete field on the full grid after `normalizeJitter()`, replaces carved-out (+inf) voxels by the largest finite value, blurs it with the periodic separable Gaussian shared with the noise families (`Lattice::periodicBlur()`), and `fieldAt()` then reads that grid (`buildSmoothed()` runs before `solveThreshold()`), so corners and junctions come out rounded like fillets and the density is still solved exactly; walls thinner than ~2 sigma vanish. `--honeycomb_angle <deg>` / `--honeycomb_rib <ratio>` (either one switches `honeycomb_custom` on) override the honeycomb presets (+30°/1 regular, −30°/2 re-entrant): θ is the inclined wall's angle to the horizontal, the rib ratio h the vertical rib length over the wall length; cell width W = 2cosθ, period P = 2(h + sinθ), and a shape with h + sinθ ≤ 0.1 folds onto itself and falls back to the preset with a warning. The **foams** (3D honeycombs: `foam_kelvin` — BCC sites, truncated octahedra; `foam_rhombic` — FCC sites, rhombic dodecahedra; `foam_weaire_phelan` — A15 sites; `foam_random` — `foam_bubbles` seeded sites with a hard core of 0.7 bubble sizes, coordinates rounded to float, or `foam_file`) are the Voronoi partition of a site set in the unit cell. `Lattice::buildFoam()` cuts each Voronoi cell out of a box with the bisector planes of all sites within twice the covering radius (`clipPolyhedron()`; a plane that leaves no cap is no neighbour — the FCC second neighbours touch the rhombic dodecahedron at its corners only), so every cell knows its true faces and edges: 14 / 36 per bubble for Kelvin, 12 / 24 rhombic, 13.5 / 34.5 on average for Weaire–Phelan (logged). `Lattice::foamField()` takes the point's nearest site and then, by `foam_mode`: *walls* — the distance to the cell boundary (exact; c = half the wall, closed cells); *windows* — `max(d, e - w)` with e the in-plane distance to the nearest face's edges and w = `foam_frame` bubble sizes, so the wall reaches c + w into the face, the window narrows as the wall thickens and any density is reachable (a fixed window capped the density at ~0.23); *edges* — the distance to the cell's edges plus the neighbours' edges leaving its vertices (an open-cell foam, matches a brute-force edge network voxel for voxel). The sites go to `Parameters::lattice_foam_sites` / `geometry/lattice_foam_sites`. Printability (trial of 360 draws on 64^3, cells 10–18 mm, density 0.15–0.5): closed walls pass from density × cell ≈ 3 mm (Kelvin, rhombic) / 4.5–5 mm (Weaire–Phelan, random), the rhombic foam has no overhang at all (walls vertical or at 45°), windows need a frame ≳ 0.2. The **mycelium** (`mycelium`, mycelium.h/.cpp — pure C++, no Qt) is a fungal colony grown in the unit cell from the seed: nodes every 0.02 cell edges along every hypha, a hypha a chain that starts on its parent's node or a spore and may end on another hypha's node (fusion). Tips take up a nutrient substrate on a periodic 32^3 grid around every new node (it diffuses; tips turn up its gradient, branch in proportion to it and stop where it is gone), branch every `mycelium_unit` of length at `mycelium_angle`, turn away from nearby hyphae, fuse within `mycelium_fuse` (0 = a tree), and every branch order is `mycelium_taper` thinner (weights 1, t, t²). `mycelium_mode` substrate (`mycelium_spores` spores, default 4, both ways), polypore (default 10 straight unbranched skeletal hyphae, then branched binding hyphae — share `mycelium_binding` of `mycelium_length` — that start on them, reach for the nearest other skeletal hypha and fuse with anything but their own; `mycelium_align` leans the skeletal hyphae to Z — u ← unit((1 − a)·u + a·e_z) — and then the binding hyphae reach as far as the fibres stand apart, ~0.8/√n, start two more per fibre, are straighter, branch less, live longer and do not fuse into their own fibre's tuft; at a = 0.7 a 64³ cell is one body joined in 3 directions with 70 % of the length along Z, at a ≥ 0.85 the near-parallel fibres tie into bundles that miss their periodic neighbours (1 of 3 seeds printable)), mat (layers z = 1/4, 3/4, 3 spores each; a share `mycelium_anchors` of the branches become thick vertical anchors that grow to the other layer and spread on there) or layered (substrate poor `mycelium_poor` at z = 0, rich in the mid plane). Normals come from Box–Muller on the shared `std::mt19937` (no `std::normal_distribution`, which differs between standard libraries). The colony is a table of straight pieces (a in [0,1)^3, b = a + vector, weight), float-rounded so `mycelium_file` rebuilds it bit for bit; F = distance to the nearest piece / its weight through a periodic bucket grid that is exact below a cut-off (2.5× the radius the pieces' own volume needs) and capped there — `Initialization()` doubles the cut-off and re-solves while c·(1 + grading + jitter) reaches it. Pieces go to `Parameters::lattice_mycelium_segments` / `geometry/lattice_mycelium_segments`, the growth statistics (`mycelium::Stats`: hyphae, branchings, fusions, free ends, growth unit, share of the length on closed loops = 2-core, fabric diagonal) to `Parameters::lattice_mycelium_stats` / `geometry/mycelium_*`. A cell grows in < 0.1 s; trial: one body joined in 3 directions in every mode, thinnest hypha 0.9–1.1 mm at density 0.2 in a 12 mm cell; the thin-wall check passes them at 64³ and 128³ (0–0.07 % thin), and at density 0.08 (thinnest twigs 0.7 mm) it flags 43 %. The **Neovius**, **Fischer–Koch S** and **Lidinoid** sheets (`*_sheet`) are level sets like the gyroid, evaluated (f and its gradient, for the uniform wall) from their exact Fourier expansions, which `cellforms::tpmsWaves()` builds by multiplying out the trigonometric products (`testNewSurfacesAndForms` checks them against the formulas; the Lidinoid's +0.15 is a zero-vector wave) and `tpmsWaves()` publishes. The **bio-inspired and architected forms** (cellforms.h/.cpp, pure C++; `isFormFamily()`, `formIndex()` maps a family onto `cellforms::Kind`, the two enums list them in the same order) are shaped by three knobs `form_a/b/c` in [0, 1], each mapped linearly onto one physical parameter of that form (`cellforms::knobLabel()` names it for the log and the Dataset Browser), so a dataset samples every form from the unit cube. *Segment forms* — `glass_sponge` (Euplectella's square grid, double diagonals in a checkerboard of squares on the vertical walls, the horizontal planes too for c > 1/2), `chiral_twist` (rings on the faces, one bar between the rings of the faces z = 0 and x = 1 repeated by the 24 proper rotations — 12 bars), `woven` (3 or 4 plain-weave layers of two warp and two weft yarns, crimp A so yarns of radius >= max(A, h/2 − A) touch), `bouligand` (8 plies of fibres along the lattice directions 0–153°, every fibre a ribbon of two lines ±1/32 about the ply so radius >= 1/32 joins the plies — a single line left the plies apart in 6 of 24 trial draws), `diamond_ball_stick`, `reentrant_3d` (ribs at the BCC columns, bars falling from a rib's top to the next foot) — return a table of weighted pieces <= 0.25 cell edges long that goes through the mycelium's bucket grid and cut-off loop (`usesPieceTable()`; not published, the knobs rebuild it). *Field forms* — `radiolarian` (shells about the cell centre and corner with pores on <100>/<110>, spines on <111>), `trabecular_bone` (seeded hard-core Voronoi in a metric stretched along Z: rod = (d3 − d1)/2 over a hashed per-edge weight, a hashed share of the faces (d2 − d1)/2 as plates), `wood` (2D Voronoi tracheids extruded along Z, wall weight 0.75 + k·late³ across a growth ring, three pits per wall at hashed heights kept 2 pit radii clear of the three-wall corners — pits at the junctions cut pieces loose), `cuttlebone` (septa every 1/chambers, walls the zero set of a 2D labyrinth field plus a corrugation whose amplitude grows to the ceiling, as |W|/|∇W|), `turing` (Gray–Scott on a periodic G^3 grid, 10 000 explicit steps with dt = 0.8 — dt = 1 sits on the stability limit and blew up —, then periodic Catmull–Rom; signed level set, no wall estimate, so the printability mean thickness stands in), `hierarchical_gyroid` (a fine gyroid sheet inside the thick one, +inf outside) — are `cellforms::Field::at()` on the unit-cell coordinates; the seeded ones draw from the algorithm's generator. Forms cannot be a `lattice_union` / `lattice_subtract` partner (one form state per cell). Old families are untouched: 12 of 12 test cells of every old kind came out voxel- and wall-identical to the previous binary. Probe trial (24 draws per group on 64^3 with the dataset ranges): 70–100 % printable and resolved. Family predicates `isPlateFamily / isSiteFamily / isSegmentFamily / isRandomFamily / isFoamFamily / isFormFamily` and `plateOrientations()` live in latticefamily.h.

**Printability check (printability.h/.cpp).** After rasterization `Lattice::checkPrintable()` runs `checkPrintability()` on the voxel cube with the thresholds from `Parameters::printThresholds()` and the voxel size derived from `lattice_cell_mm`. Four measures: *islands* — 6-connected solid components that do not wrap the periodic cube (flood fill with unwrapped coordinates; the classic wrapping-cluster test — both labyrinths of a sheet gyroid wrap, a floating blob does not; non-periodic: anchored = touches a face). The verdict fails on any island larger than `print_max_island_vox` (default 8, a 2×2×2 speck), so a floating blob of any visible size fails regardless of its share of the volume; *bodies* — the anchored components must number at most `print_max_components` (default 1): parallel slabs or separate rods each wrap the cube and so are not islands, yet they fall apart as a part (lamellar spinodoids with two closed cones did this); the report also carries the island count, the largest island and `island_fraction_box`, the same measure on the cube cut out as a plain box — what hangs loose at the side faces of a finite part; *directions* — every time the flood fill meets its own image, the offset between the two unwrapped copies is a wrapping vector, and the rank of those vectors (exact integer cross / triple products, at most 3) is the number of independent directions the body joins its periodic neighbours in: 3 for a lattice, 2 for a slab, 1 for a rod, 0 for a blob that touches no neighbour. Fewer than `print_min_directions` (default 3; periodic only, a finite part needs no path between its faces) fails, because the tiled part falls apart into layers or rods and the solver then fills the missing direction with the void: a graded Schwarz P whose thin end pinched off came out at E_z = 0.02 MPa, smoothed noise cut into sheets at 0.01 MPa, and a sheet whose layers touch only along voxel edges at E / E_s = 8e-4 for density 0.41. The rank counts, not the axes: a diagonal rod moves along X and Z and is still one direction; the verdict names an axis only when no wrapping vector moves along it (`unjoined_axes`); *thin walls* — solid removed by a morphological opening with a ball of radius `min_wall/2` voxels, built from two exact Euclidean distance transforms (separable Felzenszwalb–Huttenlocher, each line tripled for periodicity), so thickness is the true local thickness rather than a voxel count; the dilation reaches `min_wall/2` plus half a voxel diagonal, because the ball centres are voxel centres and the best one for a voxel on an inclined or curved surface lies between them — without that slack the staircase read as thin (3–14 % of a thick strut along [1 2 3], 3–6 % of a mycelium at 64³, octet struts 2 mm thick), while a wall too thin to erode is still all thin (`testThinWallsIgnoreTheVoxelStaircase`); *overhangs* — for each of the six build directions the fraction of solid with no solid in the `(2r+1)²` window of the layer below, `r = round(tan(max_overhang))`, the first layer resting on the bed; the verdict uses the best direction because the print orientation is ours to choose; *closed pores* — void in non-wrapping void components, reported but not failing. Results live in `Parameters::printability` (a `PrintabilityReport`), are logged in one line and written to the HDF5 geometry group (`print_ok`, `print_components`, `print_connected_directions`, `print_islands`, `print_largest_island_vox`, `print_island_fraction`, `print_island_fraction_box`, `print_closed_pore_fraction`, `print_thin_fraction`, `print_unsupported_best`, `print_best_direction`, `print_verdict`, `voxel_mm`, `lattice_wall_mm`). The thin-wall check needs at least one voxel per half wall (`opening_radius_vox >= 1`) and says so otherwise; `mean_thickness_vox` (4 x the mean solid-to-void distance, exact for a slab) supplies a wall estimate for families without an analytic one. Tests in `tests/test_printability.cpp` pin each measure on hand-built cubes.

`lattice_uniform_wall` (CLI `--lattice_uniform_wall`) changes how the *sheet* families are thickened: `|f| / |grad f|` — the first-order distance to the surface, with analytic gradients for the four TPMS and the Fourier sum — instead of `|f|`. A random Fourier sheet thickened by `|f|` has walls of very uneven thickness (a third to a half of the solid below 0.8 mm at typical settings); with the uniform wall the thickness is nearly constant and `c` is the half thickness in cube fractions, so the wall estimate becomes `2 c N` voxels. The flip side is that a uniform wall is only as thick as the density allows: at 25 % density with 16 waves up to 3 per edge in a 12 mm cell the uniform wall is ~0.7 mm, below the 0.8 mm minimum everywhere, so the printable density floor of a random sheet is set by its surface area — the orchestrator should sample density accordingly (or lower `fourier_kmax`, or enlarge the cell).

`relative_density` is the input, not an outcome: `F` is sampled on the full grid up to 128^3 (on a 128^3 copy above that — a 64^3 copy put axis-aligned walls on the wrong whole-voxel shell at 128^3, a rectangular honeycomb came out at 0.09 instead of 0.25), sorted, and `c` is read off at the requested quantile — exact on that grid up to *ties*, which a symmetric cell produces in whole shells (every voxel at the same distance from an axis-aligned strut flips together; the strut, plate and honeycomb distance fields are snapped to 1e-9 so rounding noise cannot split a shell into ragged walls); the side of the tie closer to the target is taken and the achieved density is always reported, together with an estimated wall/strut thickness in voxels (sheet TPMS from the surface area per cell, struts and walls from `c`), with a warning below 6 voxels where the voxel staircase distorts the homogenized stiffness. Both numbers go into `Parameters::lattice_achieved_density` / `lattice_wall_voxels` and from there into the HDF5 geometry metadata. `lattice_grading` scales the thickness linearly along Z and `lattice_jitter` modulates it with a seeded low-frequency random field (multiplicatively for distance-like fields, additively for the signed level sets); `orientation_angle_a/b/c` rotate the lattice about the cube centre, which breaks periodicity across the faces, so leave them at zero for homogenization. The family table (`latticefamily.h`: enum, CLI key, panel label, signed-level-set flag, parser accepting keys, labels and aliases) is the single source read by `Parameters::setLatticeFamily()`, the CLI validator and the algorithm. The solid is published as a single-constituent `PhaseAssignment` with the identity orientation (so an anisotropic printed material keeps its full 6x6), the material defaults to `PETG` when none is selected, and `Next_Iteration()` reveals the cell layer by layer along Z, ending on exactly the one-shot structure.

### Crystallographic texture
`TextureLibrary` (texturelibrary.h/.cpp) samples per-grain crystal orientations as Bunge ZXZ Euler angles, either uniformly random (`Mode::Random`) or from ODF texture components (`Mode::Components`, built from a `TextureLibrary::Process` preset — rolling/extrusion/recrystallization/shear — for an FCC or BCC lattice). `TextureController` + `TextureView.qml` is the interactive editor; on apply it writes into `Parameters::textureComponents`, which is the single source both stress solvers read from. Algorithm parameter panels and the CLI instead go through `Parameters::setTexturePreset()/setTextureScatter()`, which rebuild `textureComponents` from a preset via `rebuildTextureFromPreset()`. The preset `"custom"` means "owned by the editor" and suppresses that rebuild — applying in the editor sets it (`markTextureCustom()`), so a hand-edited texture is never silently overwritten. Note that the `Random` preset is represented by an *empty* `textureComponents`, which is what every existing caller already treats as uniformly random. `stressresult.h::buildGrainOrientations()` is the shared, seed-driven bridge that turns `textureComponents` into a `grain id -> orientation` table — it's called by *both* solvers so a given `Parameters::seed` produces the identical polycrystal realization in ANSYS and FFT (this is what makes `solver_compare` a fair A/B test).

### Multi-phase materials
`phasematerial.h` carries `PhaseMaterial` (a name + a **full Voigt 6x6 stiffness in Pa, in the material's own axes** — nothing assumes cubic) and `PhaseAssignment` (the material list, `grain id -> phase`, and optionally `grain id -> Bunge ZXZ orientation`). An algorithm that knows its structure has more than one constituent publishes one into `Parameters::phaseAssignment`; this is the multi-phase analogue of `Parameters::textureComponents`.

`stressresult.h::resolveGrainMaterials()` is the shared bridge — called by *both* `StressAnalysisFFT::makeSession()` and `StressAnalysis`'s `sharedGrainMaterialsFor()`, so for one seed the two backends see the identical per-grain orientation *and* constituent. An **empty or mismatched** assignment falls back to exactly the historical single-material path (`db_material`'s cubic constants + texture-sampled orientations), which is what keeps every other algorithm unchanged. `MainWindowAlgorithmHandler::executeAlgorithm()` clears the assignment before each run so a stale one can never be applied to a different structure's grain ids.

Backend specifics:
- **FFT** — `FFTSolverSession` has a second constructor taking a per-grain Voigt stiffness (material axes) and rotating each by that grain's orientation via `mvh::aniso_grain_mandel()`. The `void_C11` argument sizes the soft void phase; pass the largest C11 in play.
- **ANSYS** — `setAnisoMaterial(matId, C[6][6])` emits one `TB,ANEL,<matId>,1,21` block per constituent, and `setGrainMaterials()` gives the wrapper a `grain id -> material number` table that the EBLOCK's MAT column now reads (it used to be hardcoded to 1). Two conventions matter here, both confirmed against real v252 solves:
  - The 21 TBDATA slots are the **row-wise upper triangle** (D11 D12 D13 D14 D15 D16, D22 D23 …, D66) — the layout the previous hardcoded cubic block used. Not the column-wise order the docs suggest: that would put 0 in D33 and the material would be singular.
  - **ANSYS orders the shear components (xy, yz, xz); Voigt — and so this codebase, the material database and the FFT solver — orders them (yz, xz, xy).** `setAnisoMaterial` permutes via `A2V = {0,1,2,5,3,4}`. Without it a transversely isotropic fiber's in-plane shear modulus lands in Gxz instead of Gxy. This was invisible for as long as it was because a cubic material has all three shear moduli equal and no normal-shear coupling.

`DBManager::stiffnessMatrix()` reads all 21 columns by name, expanding rows that only have c11/c12/c44 filled into the cubic matrix those imply. `material_properties.db` now also carries composite constituents: `Epoxy`, `E-glass`, `Al2O3`, `SiC` (type `iso`), the printing plastics `PETG`, `PLA`, `ABS`, `ASA`, `PC`, `PA12`, `TPU-95A` (type `iso`, from a representative E and ν) and `C-fiber` (type `ti` — transversely isotropic **about axis 3**, which is the axis `Composite` aligns to the fiber). Seeding is per-material insert-if-absent, so an existing database picks up new rows without losing edits.

`fft_homog.hpp::pick_reference()` needed a fix for this to work at all. Its per-phase modulus estimate reads only the shear diagonal and the lambda block — it never looks at `C[0..2][0..2]` — which tracks fine for cubic crystals but comes out ~6x too soft for a transversely isotropic fiber, and the basic scheme then **diverges** (error growing, then NaN) rather than converging slowly. It now also enforces the scheme's sufficient condition directly (`2*C0 - C(x)` positive definite, using a power-iteration `lambda_max` per phase) and raises the reference when the heuristic falls short. The reference medium does not change the fixed point, only stability and rate, so this can only make an existing run more robust; it is a no-op for every cubic material in the library.

`FFTHomogenizer` has a second scheme, `Scheme::CG`: conjugate gradients on the Galerkin / projection form of the same equations (Zeman et al. 2010; Vondřejc, Zeman & Marek 2014; de Geus et al. 2017). The unknown is the zero-mean compatible strain fluctuation `e`, the operator `A e = G : C : e` uses the compatibility projection `G` (the Green operator of a reference medium with `lambda0 = 0, mu0 = 1/2` — nothing material-dependent to pick) and is symmetric positive definite on that subspace, so plain CG applies with `b = -A E`. Same fixed point as the basic scheme, iteration count ~ sqrt(contrast), 12 FFTs per iteration instead of 18. Its convergence test is the relative residual `||r||/||b|| < tol` (reported as `last_error()`, with the equilibrium error printed alongside). `FFTSolverSession::Scheme { Auto, Basic, CG }` chooses: `Auto` takes CG when the cell has a void phase or a C11 contrast above 100 and the basic scheme otherwise, so dense polycrystal runs are unchanged; `Parameters::fft_scheme / fft_tol / fft_max_iter` (CLI `--fft_scheme`, `--fft_tol`, `--fft_max_iter`) are read by `StressAnalysisFFT` at construction. On a 32^3 sheet gyroid at 30 % density (contrast 1e4) the basic scheme stalls at an equilibrium error of ~5e-2 after 1000 iterations and returns an unconverged stiffness; CG converges in ~500 iterations per load at `tol = 1e-4` (the moduli move by 0.1 % between 1e-4 and 1e-5, and by 4 % at 1e-3).

Even so, the basic scheme converges linearly in phase contrast, and it is slower than you would guess: a plain **dense Cu polycrystal** (Zener 3.2, no second phase) already needs ~800 iterations at `fft_tol` 1e-5 on a 20^3 grid, i.e. ~70 s per load case and ~7 min for the six of a stiffness run. Carbon/epoxy is ~40x contrast and will hit `fft_max_iter` (default 1000) on a full dataset build. Prefer a lower-contrast pair (E-glass/epoxy, W/Al) when iterating, or the ANSYS backend, which does not care about contrast. This is a property of the basic scheme, not of any particular algorithm — `Polycrystall` and `Voronoi` produce fully dense structures (solid fraction 1) and take the same time for the same grain count.

**Willot's rotated discretization.** `FFTHomogenizer::Discretization { Continuous, Rotated }` is set with `set_discretization()` (forwarded by `FFTSolverSession`; `Parameters::fft_discretization`, CLI `--fft_discretization`, default `continuous` so existing runs are unchanged; `StressAnalysisFFT` applies it right after the session is built). `Rotated` (Willot 2015) evaluates the continuous Green operator at the modified frequency of the rotated finite-difference stencil, `xi_j = sin(pi q_j / n_j) / (pi d_j) * prod_{m != j} cos(pi q_m / n_m)`, from per-axis tables built once in `build_wave_tables()` (the cosine is exactly 0 at Nyquist). `wave_vector()` returns the vector of the active scheme and `false` where it vanishes; `apply_green`, `apply_projection` and the equilibrium error then treat that mode as carrying no compatible strain. Why it exists: a lattice pore modelled as a phase of 1e-6..1e-8 of the solid makes the continuous operator stall or return negative moduli, while the rotated one converges, gives cleaner fields at the walls and a smaller voxel error — about 150/v^2 % against 350/v^2 % for v voxels across the thinnest wall (sheet gyroid at 30 %: E = 208.7 / 214.9 / 219.2 / 220.2 MPa at 48 / 64 / 96 / 128^3, limit ~222). Use it for lattices.

**Void stiffness.** The void is a soft isotropic phase of `void_eta * C11` (`Parameters::fft_void_eta`, CLI `--fft_void_eta`, default 1e-4; both `FFTSolverSession` constructors take it). 1e-4 is within ~1 % for stretching-dominated cells and converges fast, but a bending-dominated cell leans on the fictitious void: a re-entrant honeycomb gives E_x = 15.2 / 7.55 / 6.73 / 6.63 MPa at 1e-4 / 1e-5 / 1e-6 / 1e-8. The stiffness run therefore reports, per unit load, the share of the strain energy carried by the solid (`solid_energy_share`, = sum T : C_s over the solid / C); it is 1 without the artifact, and a clearly lower value means the cell must be re-solved with a softer void (the dataset orchestrator does that below 0.985).

**Sensitivity index and tensor.** `computeStiffnessMatrix()` keeps the six unit-load strain fields of the solid voxels and derives three things from them (static helpers in `FFTSolverSession`). The *strain-concentration index* `strain_concentration_index()` = `<|eps|^2>_solid / |<eps>_solid|^2` (engineering norm via `eng_strain_norm2()`): exactly 1 when the material deforms uniformly, ~2 for plates, ~5 for a gyroid, ~14 for BCC — a non-uniformity measure and an upper bound on how a law error is amplified, not a prediction. `solid_strain_ratio()` = `<|eps|^2>_solid / |E|^2`, how much of the cell's strain the material carries. The *sensitivity tensor* `sensitivity_tensor()` holds the second moments `T[i][j][a][b] = <eM_a^(i) eM_b^(j)>` of the six unit engineering-strain loads (gamma = 1) over the whole cell (1296 numbers, Mandel components); by Hill's lemma `predict_stiffness_change(T, dC)` gives the first-order change of the cell stiffness for any change `dC` of the material's 6x6 (for `dC = eta * C_s` it returns `eta * C` up to the void's own share of the energy), so the effect of a law error can be evaluated later without a new solve. The homogenizer orders Mandel components (xx, yy, zz, yz, xz, xy) and the pipeline (xx, yy, zz, xy, yz, xz); the permutation `{0, 1, 2, 5, 3, 4}` in `stressanalysis_fft.cpp` maps between them. Everything lands in `StiffnessMatrixResult` and the HDF5 geometry group: `sensitivity_index(_loads)`, `solid_strain_ratio(_loads)`, `solid_energy_share(_loads)`, `sensitivity_tensor` (36x36). The tensor follows the file's shear basis: in a file without the `shear_basis` attribute (unit tensor-strain loads, dataset v1) the entries with a shear second index j are twice the engineering ones.

Useful self-checks, all cheap and all falsifiable. Every one of these holds for **both** backends, and the first three are exact because a homogeneous cell is BC-independent:
- both phases the same material must return that material's own constants (Epoxy -> E = 3.509 GPa, E-glass -> 71.99 GPa);
- a 1D cell of C-fiber must return C-fiber's own constants (Ez = 230, Ex = Ey = 15, Gxy = 7.01, Gyz = Gxz = 15 GPa — S/C are in the engineering shear basis (gamma = 2*eps), so C44 = G and 1/S_ii prints the shear moduli directly);
- a two-material cell whose materials happen to be identical must return the same, which is what proves material 2 is defined and its mat_id resolves;
- a 2D crossed cell must give Ex == Ey, and a 3D orthogonal cell with an isotropic matrix Ex == Ey == Ez (FFT only — periodic);
- a UD carbon/epoxy cell must match the rule of mixtures on the axial modulus: at the achieved Vf = 0.4444, `Vf*230 + (1-Vf)*3.5` = 104.2 GPa, and ANSYS returns 104.2 GPa.

### Stress analysis: two interchangeable solver backends
`StressAnalysisController` (Q_OBJECT, exposed to QML as `stressAnalysisController`) is the single UI-facing entry point and picks between:
- **`StressAnalysis`** (stressanalysis.cpp) — drives a real ANSYS process via `ansyswrapper.cpp` (writes APDL, launches ANSYS, parses results). Needs ANSYS installed and reachable.
- **`StressAnalysisFFT`** (stressanalysis_fft.cpp) — an in-memory, dependency-free FFT homogenizer. `fft_homog.hpp` is the header-only Moulinec-Suquet basic-scheme solver (self-contained complex FFT, OpenMP-parallelized); `fft_solver_session.hpp`'s `FFTSolverSession` adapts it to the pipeline's tensor conventions (Mandel vs. pipeline strain/stress ordering — read the conventions comment at the top of that file before touching the math).

Both solvers implement the same three-phase pipeline and write the same HDF5 schema, so downstream code (`LoadStepManager`, the 3D field viewer) doesn't care which one ran:
1. **Phase 1.0** — 6 canonical unit-strain solves -> effective compliance/stiffness `S`/`C`/`P` matrices + moduli.
2. **Phase 1.5** — ~150 random loads -> least-squares fit of a Hill-ellipsoid yield criterion (`hillcriterion.cpp`).
3. **Phase 2.0** — ~300 loads sampled on the Hill ellipsoid -> full per-voxel field results written to HDF5 (via `hdf5wrapper.cpp`) and reloaded through `LoadStepManager` for visualization.

`StressAnalysisController` also exposes cheaper standalone entry points that skip phases 1.5/2.0 (single-load-case solve, and a 6-load "stiffness matrix only" computation) for fast iteration/debugging without a full dataset build.

Result types are unified in `stressresult.h` (`SingleShotResult`, `StiffnessMatrixResult`, `FieldVisualizationData`) so the controller and QML can treat ANSYS and FFT output identically.

### Threading convention
Structure generation and both solvers run off the Qt main thread via `QtConcurrent::run` + `QFutureWatcher`, per the pattern in `stressanalysiscontroller.cpp`. The worker lambdas must **not** touch QML-facing singletons (`OpenGLWidgetQML::getInstance()`, `LoadStepManager::getInstance()`) directly — those are unsynchronized and are only touched from the corresponding `on*Finished()` slot back on the main thread. If a worker needs to push incremental progress to the UI (e.g. live FFT convergence), it must marshal back via `QMetaObject::invokeMethod(controller, lambda, Qt::QueuedConnection)`, never call controller methods directly from the worker thread.

**The shared grid.** `Parameters::voxels` is used in place by a running structure generation (in the GUI it runs on the main thread, the algorithm's own array is the grid, and `executeAlgorithm`'s `updateScene()` lets the event loop run to redraw - once before filling, after every step of an animation) and by a stress solve (the worker reads it through the pointer it was given). Both count as users: `Parameters::VoxelUse` in `executeAlgorithm`, `acquireVoxels()` / `releaseVoxels()` in `StressAnalysisController::setRunning()`. Code that frees or replaces the grid checks `Parameters::voxelsBusy()` first: `Hdf5ProjectController::pushTo3DView()` (a cell opened from the Dataset / Selector tab or a project) and `NeuralGeneratorController::finish()` wait through `Parameters::whenVoxelsFree()` and show the cell when the last user is done (once, re-asking if the grid is taken again at once, as the autostart solve does); `ExportController::openHDF5()` refuses; START (`runAlgorithm`) and the three stress runs refuse while it is busy. Main thread only. Before this (2026-11-16) a cell opened during a generation or a solve freed the grid under it: SIGSEGV in `Lattice::rasterize` / `OpenGLWidgetQML::setVoxels`, or silent writes into freed memory. Anything new that assigns `Parameters::voxels` must do the same.

## Dataset orchestrator

`tools/dataset/make_dataset.py` (`plan` / `run` / `collect` / `check` / `status`, config `dataset.yaml`) runs the headless Lattice pipeline per cell and gathers `dataset.parquet` + `waves.parquet`; see `tools/dataset/README.md`. Generated data lives in `data/` (git-ignored).

`plan` draws every family block and the material law (`laws:` ranges of E, nu and print anisotropy, one law per row; `isotropic_share` (0.2) of the rows get aniso = 1, the lowest share of the aniso coordinate mapped to 1 so the other coordinates are unchanged) from a Sobol sequence; `require.min_density_x_cell` drops draws in the unprintable corner. Per row, `run` does a 64^3 probe (geometry + printability, exit 3 = `unprintable`), rejects a spinodoid/Fourier row whose wave table has |k| > `max_wave_number` (4 per box edge, the 256-number shape vector; `out_of_band`), picks the smallest grid in `grid.sizes` (64, 128 — powers of two, since Bluestein FFTs make 96^3 slower than 128^3) on which the wall spans `grid.min_wall_vox` (6) voxels (`unresolved` otherwise), solves periodic families without grading/jitter as one unit cell and pins the noise families to 64^3 (their field is drawn on the grid), then solves with Willot and void 1e-4 and re-solves at `fft_void_eta_fallback` (1e-6) when the solid carries less than `min_solid_energy_share` (0.985; 0.97 on 128^3) of the energy in any load. A cell whose solid still carries less than `min_load_path_share` (0.9) after that re-solve has no solid path in some direction (status `no_load_path`, exit 7, file kept); the probe's `print_min_directions` check normally rejects such cells first. `recheck` re-applies the current checks (probe with the current binary + the post-solve share) to rows already accepted. Quotas count accepted cells; `card.md` reports counts, grid shares and pass rates of the checks.
